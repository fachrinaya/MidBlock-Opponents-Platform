# About this report — analysis logic

## Deterministic assembly

About is built directly from evidence and provenance. It is not generated by Haiku. A change in fixture, cutoff, data coverage or review status should therefore appear without relying on prose-generation memory.

Display:

- Focus player and recorded role.
- Timezone-aware evidence cutoff and latest recorded player league fixture.
- Source system and the upcoming fixture's source/last-seen timestamp.
- Reconstructed-table status and scope; it is not an official deduction-adjusted table.
- Each metric/window's coverage and missing-data exclusions.
- Stored scoring-model identity, pool counts and per90/raw-pool distinctions.
- Shape/heatmap interpretation limits and unresolved lateral source convention.
- Model, generation time, source runs, review/editor identity and translation provenance.
- Refresh triggers: another relevant match, fixture change or availability information.

## Authorship and status

The accepted example began as a Haiku draft and required substantial factual/editorial changes before the final English translation. Keep the untouched model responses in the audit archive, separate from the reviewed example. Do not label a structurally validated new draft as factual approval.

## Readability

Keep routine definitions and coverage limits in this section so the other sections can concentrate on player preparation. The presence of an About disclosure does not permit misleading language elsewhere; a scope-sensitive number still needs a correct unit and sample label when used.

## Implementation boundary

The shared data pipeline computes the evidence once. This folder’s `pipeline.py` selects the section input, extracts the approved example output, and validates section structure/identities using `pipeline.sections`. Editing the prompt changes future draft writing; editing a formula requires a data-pipeline change and an offline rebuild. Neither action rewrites the frozen approved example automatically.
